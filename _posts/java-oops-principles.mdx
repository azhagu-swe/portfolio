# 🧠 Java OOP Principles for Interviews (2025) - Beginner-Friendly

_Your guide to mastering Java Object-Oriented Programming (OOP) principles like encapsulation, inheritance, polymorphism, and abstraction for interviews!_

## Introduction

Object-Oriented Programming (OOP) is the backbone of Java, and understanding its core principles—encapsulation, inheritance, polymorphism, and abstraction—is crucial for acing Java interviews. These concepts help you design modular, reusable, and maintainable code. This beginner-friendly guide explains each principle with clear examples, covers related concepts like overriding vs. overloading, IS-A relationships, aggregation, and composition, and answers common interview questions to prepare you effectively.

## Key Concepts

### 1. Encapsulation

Encapsulation hides an object’s internal data and provides controlled access through public methods (getters and setters). It protects data integrity and promotes modularity.

**Example**:

```java
public class Student {
    private String name; // Private field
    private int age;

    // Public getters and setters
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) {
        if (age > 0) this.age = age; // Validation
    }
}
```

**Why it matters**: Encapsulation ensures data is accessed safely, preventing invalid modifications.

### 2. Inheritance

Inheritance allows a class (subclass) to inherit fields and methods from another class (superclass) using the `extends` keyword. It promotes code reuse and establishes an **IS-A** relationship.

**Example**:

```java
class Animal {
    void eat() { System.out.println("Eating..."); }
}
class Dog extends Animal {
    void bark() { System.out.println("Woof!"); }
}
```

**Why it matters**: Inheritance reduces code duplication and supports hierarchical design.

### 3. Polymorphism

Polymorphism allows objects to be treated as instances of their superclass or interface, enabling flexibility. It’s achieved through:

- **Method Overriding**: Subclass provides a specific implementation of a superclass method.
- **Method Overloading**: Multiple methods with the same name but different parameters.

**Example (Overriding)**:

```java
class Animal {
    void sound() { System.out.println("Some sound"); }
}
class Cat extends Animal {
    @Override
    void sound() { System.out.println("Meow"); }
}
```

**Example (Overloading)**:

```java
class Calculator {
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
}
```

**Why it matters**: Polymorphism enables dynamic behavior and flexible code.

### 4. Abstraction

Abstraction hides complex implementation details and exposes only essential features. It’s achieved using **abstract classes** or **interfaces**.

**Example (Abstract Class)**:

```java
abstract class Shape {
    abstract double area(); // Abstract method
}
class Circle extends Shape {
    double radius;
    Circle(double radius) { this.radius = radius; }
    @Override
    double area() { return Math.PI * radius * radius; }
}
```

**Why it matters**: Abstraction simplifies code by focusing on what an object does, not how it does it.

### 5. Overriding vs. Overloading

- **Overriding**: Same method name, same signature (parameters and return type), different implementation in a subclass. Uses `@Override` annotation.
- **Overloading**: Same method name, different parameter lists (type, number, or order) in the same class.

**Example**:

```java
class Example {
    void display(String s) { System.out.println("String: " + s); } // Overloading
    void display(int i) { System.out.println("Int: " + i); }
}
class Parent {
    void show() { System.out.println("Parent"); }
}
class Child extends Parent {
    @Override
    void show() { System.out.println("Child"); } // Overriding
}
```

### 6. IS-A Relationship

An **IS-A** relationship indicates a subclass is a type of its superclass, established through inheritance or interface implementation.

**Example**:

```java
// Dog IS-A Animal
class Dog extends Animal {
    // Inherits Animal's methods
}
```

### 7. Aggregation

Aggregation is a **HAS-A** relationship where one class contains another, but both can exist independently (weaker relationship).

**Example**:

```java
class Department {
    String name;
    Department(String name) { this.name = name; }
}
class University {
    List<Department> departments; // Aggregation
    University() { departments = new ArrayList<>(); }
}
```

### 8. Composition

Composition is a stronger **HAS-A** relationship where the contained object’s lifecycle depends on the container.

**Example**:

```java
class Engine {
    void start() { System.out.println("Engine started"); }
}
class Car {
    Engine engine; // Composition
    Car() { engine = new Engine(); }
}
```

## Common Interview Questions

**Q1: What are the basic principles of OOP in Java?**
The basic OOP principles are:

- **Encapsulation**: Hiding data with private fields and public methods.
- **Inheritance**: Reusing code via superclass-subclass relationships.
- **Polymorphism**: Allowing objects to take multiple forms via overriding or overloading.
- **Abstraction**: Hiding implementation details using abstract classes or interfaces.

**Q2: Explain encapsulation with an example.**
Encapsulation hides data using private fields and provides access via getters/setters. Example:

```java
class BankAccount {
    private double balance;
    public double getBalance() { return balance; }
    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }
}
```

**Q3: What is inheritance, and why is it used?**
Inheritance allows a subclass to inherit fields and methods from a superclass using `extends`. It’s used for code reuse and establishing hierarchies. Example: `Dog extends Animal`.

**Q4: What is polymorphism in Java?**
Polymorphism allows objects to be treated as their superclass or interface type. It’s achieved via method overriding (runtime) or overloading (compile-time).

**Q5: Differentiate between overriding and overloading.**

- **Overriding**: Same method name and signature in a subclass, different implementation.
- **Overloading**: Same method name, different parameters in the same class.

**Q6: What is abstraction in Java?**
Abstraction hides implementation details and exposes essential features using abstract classes or interfaces. Example: `abstract class Shape { abstract double area(); }`.

**Q7: Can we achieve abstraction without an abstract class?**
Yes, abstraction can be achieved using **interfaces**. Example:

```java
interface Vehicle {
    void start();
}
class Bike implements Vehicle {
    public void start() { System.out.println("Bike started"); }
}
```

**Q8: What is an IS-A relationship?**
An IS-A relationship indicates a subclass is a type of its superclass or interface (e.g., `Cat` IS-A `Animal` via inheritance).

**Q9: Explain the difference between aggregation and composition.**

- **Aggregation**: A HAS-A relationship where objects are independent (e.g., `University` has `Departments`).
- **Composition**: A stronger HAS-A relationship where the contained object depends on the container (e.g., `Car` has `Engine`).

**Q10: Can a class extend multiple classes in Java?**
No, Java does not support multiple inheritance of classes to avoid complexity (e.g., the diamond problem). A class can implement multiple interfaces instead.

**Q11: What is the diamond problem?**
The diamond problem occurs in multiple inheritance when a class inherits from two classes that share a common superclass, causing ambiguity in method resolution. Java avoids this by allowing only single class inheritance.

**Q12: Can we override a static method?**
No, static methods belong to the class, not instances, so they cannot be overridden. They can be hidden by defining a static method with the same signature in a subclass.

**Q13: Can we override a private method?**
No, private methods are not visible to subclasses, so they cannot be overridden.

**Q14: What is method overloading?**
Method overloading is defining multiple methods with the same name but different parameter lists (type, number, or order) in the same class.

**Q15: What is method overriding?**
Method overriding is when a subclass provides a specific implementation of a superclass method with the same name, parameters, and return type.

**Q16: What is the use of the `super` keyword in inheritance?**
The `super` keyword:

- Calls the superclass constructor (`super()`).
- Accesses superclass methods or fields (`super.method()`).

**Example**:

```java
class Parent {
    void display() { System.out.println("Parent"); }
}
class Child extends Parent {
    void display() {
        super.display(); // Calls Parent's display
        System.out.println("Child");
    }
}
```

**Q17: What is dynamic method dispatch?**
Dynamic method dispatch is Java’s mechanism to resolve overridden method calls at runtime based on the actual object type, enabling runtime polymorphism.

**Example**:

```java
Animal animal = new Dog();
animal.sound(); // Calls Dog’s sound method
```

**Q18: Can we achieve runtime polymorphism without inheritance?**
Yes, runtime polymorphism can be achieved using interfaces. An object implementing an interface can be referenced by the interface type, and the actual method called is resolved at runtime.

**Q19: What is the difference between compile-time and runtime polymorphism?**

- **Compile-time (Static) Polymorphism**: Resolved via method overloading or operator overloading (not in Java).
- **Runtime (Dynamic) Polymorphism**: Resolved via method overriding or interfaces.

**Q20: What is an abstract class?**
An abstract class cannot be instantiated and may contain abstract (unimplemented) and concrete methods. It’s used to define a common blueprint.

**Q21: Can an abstract class have a constructor?**
Yes, an abstract class can have a constructor to initialize fields, called by subclass constructors.

**Q22: What is the purpose of the `final` keyword in inheritance?**
The `final` keyword:

- Prevents a class from being extended (`final class MyClass`).
- Prevents a method from being overridden (`final void myMethod()`).

**Q23: Can we declare a class as both `abstract` and `final`?**
No, an `abstract` class requires subclasses to extend it, while `final` prevents extension. Combining them is contradictory and causes a compilation error.

**Q24: What is a covariant return type?**
A covariant return type allows an overridden method to return a more specific type than the superclass method’s return type.

**Example**:

```java
class Animal {
    Animal getInstance() { return this; }
}
class Dog extends Animal {
    @Override
    Dog getInstance() { return this; } // Covariant return
}
```

**Q25: What is the difference between `HAS-A` and `IS-A` relationships?**

- **IS-A**: Inheritance-based, where a subclass is a type of superclass (e.g., `Dog` IS-A `Animal`).
- **HAS-A**: Ownership-based, via aggregation (independent objects) or composition (dependent objects).

## Code Example

Here’s a program demonstrating OOP principles:

```java
// Encapsulation
class Employee {
    private String name;
    private double salary;

    public Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }
    public String getName() { return name; }
    public void setSalary(double salary) {
        if (salary > 0) this.salary = salary;
    }
}

// Inheritance and Polymorphism
abstract class Vehicle {
    abstract void drive();
}
class Car extends Vehicle { // IS-A relationship
    Engine engine; // Composition
    Car() { engine = new Engine(); }
    @Override
    void drive() { System.out.println("Car driving"); engine.start(); }
}
class Engine {
    void start() { System.out.println("Engine started"); }
}

// Aggregation
class Company {
    List<Employee> employees; // HAS-A relationship
    Company() { employees = new ArrayList<>(); }
    void addEmployee(Employee e) { employees.add(e); }
}

public class OOPDemo {
    public static void main(String[] args) {
        // Encapsulation
        Employee emp = new Employee("Alice", 50000);
        emp.setSalary(60000);
        System.out.println("Employee: " + emp.getName());

        // Inheritance and Polymorphism
        Vehicle car = new Car(); // Dynamic dispatch
        car.drive();

        // Aggregation
        Company company = new Company();
        company.addEmployee(emp);
    }
}
```

**Output**:

```
Employee: Alice
Car driving
Engine started
```
