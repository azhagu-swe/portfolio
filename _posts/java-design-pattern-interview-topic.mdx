# 🧠 Java Design Patterns for Interviews (2025) - Beginner-Friendly

_Your simple guide to mastering Java design patterns like Singleton, Factory, Builder, and Strategy for interviews!_

## Introduction
Design patterns are like reusable recipes for solving common coding problems in a clean, efficient way. They help you write flexible and maintainable code, which is a big deal in Java interviews. This beginner-friendly guide explains four key patterns—**Singleton**, **Factory**, **Builder**, and **Strategy**—in a simple, easy-to-understand way with examples and suggested interview questions to help you shine.

## Key Concepts

### 1. Singleton Pattern
The **Singleton** pattern ensures only one instance of a class exists in the entire program and provides a single point to access it. Think of it like a TV remote—there’s only one remote for the TV, and everyone uses it.

**When to use**: When you need exactly one instance, like a configuration manager or a database connection.

**Example**:
```java
public class Singleton {
    // Private static instance
    private static Singleton instance;
    
    // Private constructor to prevent instantiation
    private Singleton() {}
    
    // Public method to get the single instance
    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
    
    public void showMessage() {
        System.out.println("I’m the only Singleton!");
    }
}
```

**Usage**:
```java
Singleton s1 = Singleton.getInstance();
Singleton s2 = Singleton.getInstance();
System.out.println(s1 == s2); // true (same instance)
s1.showMessage(); // I’m the only Singleton!
```

**Why it matters**: Singleton ensures controlled access and saves memory by avoiding multiple instances.

### 2. Factory Pattern
The **Factory** pattern creates objects without specifying the exact class. Imagine a toy factory that makes different toys (cars, dolls) based on what you ask for, without you knowing the details of how they’re made.

**When to use**: When you want to create objects based on a condition or type, like creating different types of notifications (email, SMS).

**Example**:
```java
interface Animal {
    void speak();
}

class Dog implements Animal {
    public void speak() { System.out.println("Woof!"); }
}

class Cat implements Animal {
    public void speak() { System.out.println("Meow!"); }
}

class AnimalFactory {
    public Animal createAnimal(String type) {
        if (type.equals("Dog")) return new Dog();
        if (type.equals("Cat")) return new Cat();
        return null;
    }
}
```

**Usage**:
```java
AnimalFactory factory = new AnimalFactory();
Animal animal = factory.createAnimal("Dog");
animal.speak(); // Woof!
```

**Why it matters**: Factory hides object creation logic, making code flexible and easy to extend.

### 3. Builder Pattern
The **Builder** pattern builds complex objects step-by-step. Think of building a custom pizza—you choose the crust, sauce, and toppings one at a time, then get the final pizza.

**When to use**: When an object has many optional attributes, like a configuration object or a complex model.

**Example**:
```java
class Pizza {
    private String crust;
    private String sauce;
    private String topping;

    private Pizza(Builder builder) {
        this.crust = builder.crust;
        this.sauce = builder.sauce;
        this.topping = builder.topping;
    }

    public static class Builder {
        private String crust;
        private String sauce;
        private String topping;

        public Builder crust(String crust) {
            this.crust = crust;
            return this;
        }
        public Builder sauce(String sauce) {
            this.sauce = sauce;
            return this;
        }
        public Builder topping(String topping) {
            this.topping = topping;
            return this;
        }
        public Pizza build() {
            return new Pizza(this);
        }
    }

    @Override
    public String toString() {
        return "Pizza [crust=" + crust + ", sauce=" + sauce + ", topping=" + topping + "]";
    }
}
```

**Usage**:
```java
Pizza pizza = new Pizza.Builder()
    .crust("Thin")
    .sauce("Tomato")
    .topping("Cheese")
    .build();
System.out.println(pizza); // Pizza [crust=Thin, sauce=Tomato, topping=Cheese]
```

**Why it matters**: Builder makes object creation readable and flexible, especially for objects with many fields.

### 4. Strategy Pattern
The **Strategy** pattern defines a family of algorithms and lets you switch between them at runtime. Imagine choosing how to pay for something—cash, credit, or mobile app—without changing the checkout process.

**When to use**: When you need to swap behaviors, like sorting algorithms or payment methods.

**Example**:
```java
interface PaymentStrategy {
    void pay(int amount);
}

class CreditCardPayment implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("Paid " + amount + " with Credit Card");
    }
}

class PayPalPayment implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("Paid " + amount + " with PayPal");
    }
}

class PaymentContext {
    private PaymentStrategy strategy;

    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    public void pay(int amount) {
        strategy.pay(amount);
    }
}
```

**Usage**:
```java
PaymentContext context = new PaymentContext();
context.setStrategy(new CreditCardPayment());
context.pay(100); // Paid 100 with Credit Card
context.setStrategy(new PayPalPayment());
context.pay(200); // Paid 200 with PayPal
```

**Why it matters**: Strategy allows you to change behavior dynamically without modifying the core logic.

## Suggested Interview Questions with Answers and Examples

**Q1: What is a design pattern, and why are they important in Java?**  
**Answer**: A design pattern is a reusable solution to a common problem in software design. They make code more modular, reusable, and maintainable, which is critical for scalable Java applications.  
**Example**: The Singleton pattern ensures a single database connection instance, saving resources.

**Q2: How does the Singleton pattern work, and when would you use it?**  
**Answer**: Singleton ensures one instance of a class using a private constructor and a static method to access it. Use it for shared resources like loggers or configuration managers.  
**Example**:
```java
Singleton singleton = Singleton.getInstance();
singleton.showMessage(); // I’m the only Singleton!
```

**Q3: What is the Factory pattern, and how does it simplify object creation?**  
**Answer**: Factory encapsulates object creation, returning objects based on input without exposing creation logic. It simplifies adding new types.  
**Example**:
```java
Animal animal = new AnimalFactory().createAnimal("Cat");
animal.speak(); // Meow!
```

**Q4: Why use the Builder pattern instead of constructors for complex objects?**  
**Answer**: Builder constructs objects step-by-step, making code readable and flexible for optional fields, unlike constructors which can become unwieldy.  
**Example**:
```java
Pizza pizza = new Pizza.Builder().crust("Thick").build();
System.out.println(pizza); // Pizza [crust=Thick, sauce=null, topping=null]
```

**Q5: How does the Strategy pattern support flexibility in code?**  
**Answer**: Strategy allows swapping algorithms at runtime by defining them in separate classes, keeping the core logic unchanged.  
**Example**:
```java
PaymentContext context = new PaymentContext();
context.setStrategy(new PayPalPayment());
context.pay(50); // Paid 50 with PayPal
```

**Q6: Can you combine design patterns? Give an example.**  
**Answer**: Yes, patterns can be combined. For example, a Factory can create Builder objects for different types.  
**Example**:
```java
interface ProductBuilder {
    Product build();
}
class CarBuilder implements ProductBuilder {
    public Product build() { return new Product("Car"); }
}
class ProductFactory {
    ProductBuilder createBuilder(String type) {
        if (type.equals("Car")) return new CarBuilder();
        return null;
    }
}
class Product {
    String name;
    Product(String name) { this.name = name; }
}
```

**Q7: What are the drawbacks of the Singleton pattern?**  
**Answer**: Singleton can make testing difficult due to global state and may cause issues in multithreaded environments if not implemented carefully (e.g., without synchronization).  
**Example**: Use double-checked locking for thread-safe Singleton:
```java
public class ThreadSafeSingleton {
    private static volatile ThreadSafeSingleton instance;
    private ThreadSafeSingleton() {}
    public static ThreadSafeSingleton getInstance() {
        if (instance == null) {
            synchronized (ThreadSafeSingleton.class) {
                if (instance == null) {
                    instance = new ThreadSafeSingleton();
                }
            }
        }
        return instance;
    }
}
```

**Q8: How does the Builder pattern differ from the Factory pattern?**  
**Answer**: Builder creates complex objects step-by-step, focusing on configuration; Factory creates objects in one step, focusing on type selection.  
**Example**: Builder for a pizza with multiple attributes vs. Factory for creating different animal types.

## Code Example
Here’s a program combining all four design patterns:
```java
// Singleton
class Logger {
    private static Logger instance;
    private Logger() {}
    public static Logger getInstance() {
        if (instance == null) {
            instance = new Logger();
        }
        return instance;
    }
    public void log(String message) {
        System.out.println("Log: " + message);
    }
}

// Factory
interface Vehicle {
    void drive();
}
class Bike implements Vehicle {
    public void drive() { System.out.println("Riding a bike"); }
}
class VehicleFactory {
    public Vehicle createVehicle(String type) {
        if (type.equals("Bike")) return new Bike();
        return null;
    }
}

// Builder
class House {
    private String walls;
    private String roof;
    private House(Builder builder) {
        this.walls = builder.walls;
        this.roof = builder.roof;
    }
    public static class Builder {
        private String walls;
        private String roof;
        public Builder walls(String walls) { this.walls = walls; return this; }
        public Builder roof(String roof) { this.roof = roof; return this; }
        public House build() { return new House(this); }
    }
    @Override
    public String toString() { return "House [walls=" + walls + ", roof=" + roof + "]"; }
}

// Strategy
interface SortStrategy {
    void sort(int[] arr);
}
class BubbleSort implements SortStrategy {
    public void sort(int[] arr) { System.out.println("Bubble sorting: " + Arrays.toString(arr)); }
}
class SortContext {
    private SortStrategy strategy;
    public void setStrategy(SortStrategy strategy) { this.strategy = strategy; }
    public void sort(int[] arr) { strategy.sort(arr); }
}

public class DesignPatternsDemo {
    public static void main(String[] args) {
        // Singleton
        Logger logger = Logger.getInstance();
        logger.log("Starting application");

        // Factory
        VehicleFactory factory = new VehicleFactory();
        Vehicle vehicle = factory.createVehicle("Bike");
        vehicle.drive(); // Riding a bike

        // Builder
        House house = new House.Builder()
            .walls("Brick")
            .roof("Tile")
            .build();
        System.out.println(house); // House [walls=Brick, roof=Tile]

        // Strategy
        SortContext sorter = new SortContext();
        sorter.setStrategy(new BubbleSort());
        sorter.sort(new int[]{5, 2, 8}); // Bubble sorting: [5, 2, 8]
    }
}
```

**Output**:
```
Log: Starting application
Riding a bike
House [walls=Brick, roof=Tile]
Bubble sorting: [5, 2, 8]
```
