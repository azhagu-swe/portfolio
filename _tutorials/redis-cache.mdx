## What is Redis?

**Redis (Remote Dictionary Server)** is an open-source, in-memory, key-value data store. That's a mouthful, so let's break it down:

-   **In-Memory**: Unlike traditional databases that store most of their data on disk (like an SSD or HDD), Redis keeps the entire dataset in RAM. This makes it incredibly fast, with read and write operations often taking less than a millisecond.
-   **Key-Value Store**: At its simplest, Redis maps keys to values, much like a dictionary or a hash map in a programming language.
-   **Data Structure Store**: Redis is more than just a simple key-value store. Its values can be complex data structures, like lists, sets, hashes, and sorted sets.

While Redis can be used as a primary database, its speed makes it most famous for its use as a high-performance **cache** and **message broker**.

## 1. The Primary Use Case: Caching

Imagine your web application needs to fetch some complex data from a traditional SQL database. This query might take 200 milliseconds to execute. If you get 100 requests per second for this data, your database will be under constant strain.

This is where a cache like Redis comes in. The workflow looks like this:

1.  A request for data comes into your application.
2.  Your application first checks if the data exists in the Redis cache.
3.  **Cache Hit**: If the data is in Redis, it's returned to the user almost instantly (e.g., in <1ms). The database is never touched.
4.  **Cache Miss**: If the data is not in Redis, your application queries the main database (the "source of truth").
5.  The application then stores a copy of this data in the Redis cache before returning it to the user.
6.  The next time a request comes in for the same data, it will be a cache hit.

![Cache Workflow](https://placehold.co/600x250/9AE6B4/1A202C?text=App+->+Redis+Cache+?->+Database)

This simple pattern dramatically reduces the load on your primary database and significantly decreases latency for your users.

## 2. Basic Redis Commands

You can interact with Redis using a command-line interface called `redis-cli`.

### Strings
The simplest data type in Redis is the string. The commands are `SET` (to create or overwrite a value) and `GET` (to retrieve it).

```bash
# Set the value of the key "user:1:name" to "Azhagu"
SET user:1:name "Azhagu"
# Response: OK

# Get the value of the key "user:1:name"
GET user:1:name
# Response: "Azhagu"
```

It's a common convention to use colons (`:`) to create namespaces for keys.

We can also set an expiration time on a key, which is perfect for caching. The `EX` option sets the expiration in seconds.

```bash
# Set the key "session:123" with a value and an expiration of 60 seconds
SET session:123 "some-session-data" EX 60
# Response: OK
```
After 60 seconds, this key will be automatically deleted by Redis.

## 3. Redis Data Structures

The real power of Redis comes from its support for more complex data structures.

### Lists
A Redis List is a list of strings, sorted by insertion order. You can push elements to the left (head) or right (tail).

```bash
# Add an element to the right of the list "my-tasks"
RPUSH my-tasks "learn redis"
# Response: (integer) 1

# Add another element to the right
RPUSH my-tasks "build an app"
# Response: (integer) 2

# Get all elements in the list (0 to -1 means from start to end)
LRANGE my-tasks 0 -1
# Response:
# 1) "learn redis"
# 2) "build an app"
```

### Hashes
A Hash is a map of field-value pairs, perfect for storing objects.

```bash
# Set multiple fields for the key "user:1"
HSET user:1 name "Azhagu" email "azhagu@example.com" age 30
# Response: (integer) 3

# Get the value of a single field
HGET user:1 name
# Response: "Azhagu"

# Get all fields and values
HGETALL user:1
# Response:
# 1) "name"
# 2) "Azhagu"
# 3) "email"
# 4) "azhagu@example.com"
# 5) "age"
# 6) "30"
```

### Sets
A Set is an unordered collection of unique strings.

```bash
# Add members to the set "tags:post:1"
SADD tags:post:1 "redis" "java" "caching"
# Response: (integer) 3

# Add another member (duplicates are ignored)
SADD tags:post:1 "redis"
# Response: (integer) 0

# Get all members of the set
SMEMBERS tags:post:1
# Response:
# 1) "caching"
# 2) "redis"
# 3) "java"
```
